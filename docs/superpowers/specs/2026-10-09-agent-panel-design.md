# agent-panel 設計

- 日期：2026-10-09
- 狀態：已實作，2026-10-09 改版，2026-10-10 加上像素小人，同日再加上圖片版小人、補齊失敗卡片細節、圖片改傳 PNG、縮小方塊版小人（改了什麼、為什麼改，見文末「2026-10-09 改版」「2026-10-10 像素小人」「2026-10-10 圖片版小人」「2026-10-10 失敗卡片細節」「2026-10-10 圖片改傳 PNG」「2026-10-10 縮小方塊版小人」）
- 位置：`my-mods/agent-panel/`（my-mods marketplace 的新 mod）

## 目的

Claude 派出子代理時，自動跳出一個面板，一眼看出這一批子代理各自在做什麼、用什麼模型、跑了多久、用了多少 token，有沒有卡住或失敗。完成後停用功能重疊的 `agent-radar@claude-code-mods`。

## 已確認的決定

| 項目 | 決定 |
| --- | --- |
| 位置 | 以右側窄欄設計（向 Claude Code 要求約 42 欄寬）；Claude Code 全螢幕版面且終端機至少 110 欄時停靠右邊，否則由 Claude Code 放到輸入框上方。放在輸入框上方時，或子代理多到完整版面放不下時，改用每個子代理一列的精簡模式 |
| 跳出時機 | 這一回合派出第一個子代理時自動開啟；另有 `/agents` 指令手動開關 |
| 範圍 | 只列這一回合派出的子代理；頂端狀態列的數量與整批耗時也只算這一批 |
| 每個子代理 | 類型（或 Agent 呼叫給的 name）、描述、模型、effort、工具次數、正在做什麼與這一步耗時、ctx %、token、時間；執行中的另有進度條。不顯示費用 |
| 進度 | 工具次數加正在做什麼；進度條只在執行中畫彗星動畫，不假裝知道百分比；完成、失敗不畫進度條 |
| 卡住提醒 | 同一個工具超過 3 分鐘、或思考超過 5 分鐘，正在做什麼那一列轉黃，進度條變成靜止的黃色 |
| 像素小人 | 完整模式每張卡片左邊畫一個 Claude 吉祥物風格的像素小人（橘色方身體、兩個眼睛、兩側小手），頭上的配件有 7 種、依派出順序輪流，看配件就知道是哪個子代理；執行中走路，卡住停下變黃，完成閉眼，失敗變灰。精簡模式、文字區太窄、不是終端機畫面時不畫 |
| 小人的畫法 | 兩種：圖片版用 mod API 的 `Image` 元件（真圖片，kitty 圖片協定）；方塊版用 `Raster` 元件（每格一個字元、前景色、背景色），半格方塊 `▀`／`▄`／`█` 讓一格畫上下兩個像素。有設定環境變數 `CLAUDE_CODE_FORCE_TERMINAL_IMAGES`（非空）、而且是終端機畫面、拿得到 `Image` 時畫圖片版；沒有那個變數時畫方塊版 |
| 圖片版小人 | 16×16 像素的小人，最近鄰放大 4 倍成 64×64 後交給終端機縮放到 4 欄 × 2 列；執行中、完成、失敗都一樣大，卡片文字區少 5 欄（方塊版少 6 欄）。用環境變數判斷，是因為 mod 沒辦法得知終端機最後到底有沒有開啟圖片，而這個變數在 Claude Code 的圖片開關裡優先順序最高。開啟方式見文末「2026-10-10 圖片版小人」 |
| 小人的造型 | 派出時記下造型編號，挑這一批還沒用掉的最小號碼：跨回合還在跑的子代理保留原本的造型，新派的不會跟它撞；超過 7 個才會重複 |
| 關閉 | 使用者本人送出一般訊息、而且這一批已全部結束時，由 mod 自己關閉；還有子代理在跑就不關 |
| 面板沒放上畫面時 | 有子代理在跑就在輸入框下方釘一行狀態列 |
| agent-radar | 本 mod 驗證完成後停用（不解除安裝） |
| 標籤語言 | 標籤用英文（Agents、Running、Failed、Done、tool／tools、ctx、starting）；正在做什麼、失敗原因用繁體中文 |

## 不做的事

- 不顯示任務名稱（截圖裡的「Launch kit」）
- 不顯示費用：token 乘單價只能估算，2026-10-09 改版拿掉
- 不顯示 Claude Code 子代理清單第二段的進度摘要：那是 Claude Code 另外產生的，mod API 拿不到；改用「正在做什麼」
- 不自己判斷終端機能不能顯示圖片：mod 拿不到 Claude Code 最後的判斷，圖片版小人只看環境變數 `CLAUDE_CODE_FORCE_TERMINAL_IMAGES`，沒有設定就畫方塊版（見文末「2026-10-10 圖片版小人」）
- 不顯示 heavy／light 這類模型分級（那是 switchboard mod 的功能）
- 不做待辦清單式的 x/y 進度
- 不做整個 session 的累計
- 面板裡不放按鈕

## 前提（來自 Claude Code 2.1.295 的 mod API）

| 事實 | 影響 |
| --- | --- |
| 窗格只有在全螢幕（alternate screen）版面、終端機至少 110 欄時才停靠在右邊；一般畫面一律放在輸入框上方 | 版面要在窄欄與整寬兩種位置都能看 |
| `Pane` 的 render props 有 `placement`（`dock` 停靠右邊、`inline` 輸入框上方）、`bodyColumns`、`scroll.bodyRows`（面板最多能用的列數） | 依這三個值決定寬度，以及要不要改用精簡模式 |
| mod 自己開的窗格（unasked）要終端機至少 144 欄才會放；使用者親手開過同一個窗格後降到 110 欄，紀錄跨 session 保留，直到使用者手動關閉窗格（✕ 或 ctrl+x x） | 提供 `/agents` 讓使用者親手開一次；mod 一律用 `$.ui.close` 關，不清掉紀錄 |
| `agent.spawn` 的輸入有 `description`、`subagentType`（`general-purpose`、`Explore`、外掛的 agent…）與 `name`（Agent 呼叫有給才有）；`next(e)` 回傳 `agentId` | 卡片標題用類型或 name，跟 Claude Code 自己的子代理清單（↓ to manage）第一段對得起來 |
| `turn.step`（串流事件）在子代理每次送出請求時觸發，輸入有 `model`、`effort`、`agentId`，結果有 `usage`（`input_tokens`、`output_tokens`、`cache_read_input_tokens`、`cache_creation_input_tokens`） | 每個子代理的模型、effort、token 都拿得到；送出請求就是「思考中」的起點 |
| API 不提供美元費用，token 乘單價也分不出 cache 存 5 分鐘還是 1 小時 | 不顯示費用，也不維護單價表 |
| `$.ui.status(text)` 在輸入框下方釘一行文字，每個外掛一行，傳 `undefined` 清掉 | 面板沒放上畫面時用它當保底 |
| 外掛不能把鍵盤焦點從輸入框搶過來 | 面板不放按鈕，不需要焦點 |
| `Raster` 元件用格子畫圖：每格一個字元、前景色、背景色（`cells` 是每格三個 little-endian u32 再轉 base64），`0x01000000` 是終端機預設色；只有終端機畫得出來，其他介面（例如 desktop）會畫成空的 | 方塊版小人用 `Raster` 以半格方塊畫，透明的地方用終端機預設色；畫面不是終端機（`surface` 不是 `terminal`）時不畫 |
| `Image` 元件畫真圖片：`source` 給 `{ rgba, width, height }`（base64）或 PNG，由終端機縮放到指定的欄數 × 列數；要終端機支援 kitty 圖片協定，畫不出圖片的地方改畫 `alt` 文字；同樣只有終端機畫得出來。mod 拿不到 Claude Code 最後有沒有開啟圖片 | 圖片版小人用 `Image`；要不要用只看下一列的環境變數 |
| Claude Code 的圖片開關：環境變數 `CLAUDE_CODE_FORCE_TERMINAL_IMAGES` 優先順序最高，非空就開，蓋過「背景 session」與「tmux」的關閉判斷；沒設定時依 `TERM` 認終端機，認不出 cmux，背景 session 預設也不開 | 有這個變數就代表圖片會開，用它決定畫圖片版還是方塊版；在 cmux 裡要用它強制開啟（cmux 實測能顯示 kitty 圖片） |
| 背景 session 繼承背景服務（`claude daemon`）啟動時的環境變數 | 改完 shell 設定後要重啟背景服務，背景 session 才讀得到；`register.tsx` 在 `session.start` 讀一次環境變數 |

## 架構

| 檔案 | 職責 |
| --- | --- |
| `hooks/batch.ts` | 批次資料與更新規則，全部是純函式：開新一批、新增子代理（含類型、name 與小人的造型編號）、記錄一次請求的用量、思考中、工具呼叫、Agent 工具結果的總計、標成完成或失敗、整批耗時 |
| `hooks/pricing.ts` | 模型 id 轉顯示名稱與系列、各模型的 context 上限、ctx %（檔名沿用；2026-10-09 改版後不再有單價表與費用計算） |
| `hooks/layout.ts` | 版面用的純函式：依顯示寬度截斷、時間與 token 的格式、狀態列文字、分組順序、完整或精簡模式、完整模式的列數與同組卡片之間要不要空一列、各狀態卡片的列與顏色、卡住判斷、以小人種類（image／raster）決定欄寬、列數、要不要畫與卡片文字寬度、每張卡片的小人（造型、狀態，方塊版另有大小）、工具呼叫的描述文字（用字與 clean-view 的 `describe` 一致；mod 之間不能共用程式碼，所以複製一份） |
| `hooks/mascot.ts` | 方塊版像素小人，全部是純函式、不 import `claude-code`：身體與 7 種配件的像素圖、各狀態的身體色與眼睛、走路的腳、把像素併成 `Raster` 的格子（半格方塊），以及 `cells` 的編碼；另外 export 圖片版共用的配色（配件、眼睛、各狀態的身體色）、走路速度、取餘數與 base64 編碼 |
| `hooks/mascot-image.ts` | 圖片版像素小人，全部是純函式、不 import `claude-code`：16×16 畫布的身體、腳、眼睛與 7 種配件的像素圖，最近鄰放大成 64×64 後用 `png.ts` 編成 PNG；`mascotImage({ look, state, frame })` 回傳 `{ png }`（完整 PNG 的 base64，每張約 432～592 字元），同一組參數有快取、回傳同一個凍結物件；`MASCOT_IMAGE_COLUMNS = 4`、`MASCOT_IMAGE_ROWS = 2` |
| `hooks/png.ts` | 把 RGBA 像素編成完整的 PNG：`encodePng({ pixels, width, height })` 回傳 bytes（8 bit RGBA、不交錯，只有 IHDR、IDAT、IEND），純函式、同步、不 import 任何模組。自己實作 zlib／deflate（RFC 1950／1951）：只用一個固定 Huffman 碼的區塊，LZ77 只找呼叫端給的回頭距離（前一個像素、上一列同位置），每列的 filter byte 一律是 0；尺寸不合理或像素數量對不上就丟例外。為什麼不用現成的壓縮，見文末「2026-10-10 圖片改傳 PNG」 |
| `hooks/register.tsx` | 接事件、開關窗格、計時器、輸入框下方的狀態列、在 `session.start` 讀一次 `CLAUDE_CODE_FORCE_TERMINAL_IMAGES`、把 `layout.ts` 算好的結果與小人（`Image` 或 `Raster`）畫成元素；盡量薄 |
| `types/index.d.ts` | state 合約 |
| `tests/*.test.ts(x)` | 見「測試」 |

`layout.ts` 是寫 spec 時從 `register.tsx` 拆出來的，讓版面規則能不經畫面直接測試；`mascot.ts`、`mascot-image.ts` 也一樣，小人的尺寸、編碼與各狀態不經畫面就能測。

### 資料模型

```ts
type AgentStatus = 'running' | 'done' | 'failed'

type AgentRow = {
  id: string
  description: string
  agentType: string                 // agent.spawn 的 subagentType
  agentName: string | null          // Agent 呼叫給的 name；沒給是 null
  isNested: boolean                 // 由子代理再派出的
  status: AgentStatus
  startedAt: number
  endedAt: number | null
  failureReason: string | null      // 已中斷、API 錯誤、模型拒絕
  model: string | null              // 最後一次請求的模型 id
  effort: string | number | null    // 最後一次請求的 effort
  toolCount: number
  activity: string                  // 正在做什麼：「思考中」或工具描述；結束後保留，失敗卡片用來說停在哪個動作
  activityStartedAt: number         // 這一步開始的時間，算這一步耗時與卡住提醒
  lastUsage: TokenUsage | null      // 最後一次請求的 4 種 token 數
  reportedTokens: number | null     // 前景子代理完成時 Agent 工具結果的 totalTokens；有值時以它為準
  look: number                      // 小人的造型編號，0 是第一種（天線），超過造型數取餘數；派出時挑這一批還沒用掉的最小號碼。舊版程式記錄的列沒有這個欄位，讀的時候當成 0
}

type Batch = { turnId: string; agents: AgentRow[] }
```

state 合約：

```ts
'agent-panel': {
  batch: Batch | null   // 最近一批
  tick: number          // 動畫計數器，只有面板讀
}
```

資料存在 `$.state`，熱重載後仍在；模組自己的變數（目前主回合的 turnId、計時器、是否已提示過）重載後重來。

## 資料收集

| 事件 | 處理 |
| --- | --- |
| `turn.start`（主迴圈，沒有 `agentId`） | 記下目前主回合的 turnId |
| `agent.spawn` | 先 `next(e)`；有 `deny` 或沒有 `agentId`（workflow 遠端子代理）或有 `teammateId` 就不處理。批次為空或 turnId 不是目前主回合時開新一批：上一批還在跑的帶過來，已完成的清掉。目前主回合的 turnId 不明（剛熱重載，模組變數歸零）時沿用現有批次，不開新的。加入新的一列：記下 `subagentType`、`name`，`isNested` 看 `parentAgentId`，這一步從派出時算起；小人的造型編號 `look` 取這一批（含帶過來的）還沒用掉的最小號碼。開了新的一批時開窗格 |
| `turn.step` | 串流 hook，`const r = yield* next(e)` 原樣傳遞；只處理帶 `agentId` 而且在這一批裡的：送出請求時正在做什麼改成「思考中」並記下開始時間，請求結束後記模型、effort、`lastUsage` |
| `tool.call`（帶 `agentId`） | 只處理在這一批裡的：工具次數 +1，正在做什麼改成這個工具的描述並記下開始時間；照原樣 `next(e)` |
| `tool.call`（主迴圈的 `Agent`） | 前景子代理完成時，工具結果帶 Claude Code 自己算的 `totalTokens`、`totalToolUseCount`，記成這個子代理的 token 與工具次數 |
| `turn.complete`（帶 `agentId`） | `answer` 標成完成；`aborted`、`error`、`refusal` 標成失敗，原因分別是「已中斷」「API 錯誤」「模型拒絕」；保留最後的正在做什麼 |
| `prompt.submit` | 使用者本人送出的一般訊息（`origin.kind` 是 `composer` 或 `bridge`，文字不是 `/` 開頭），而且這一批沒有子代理在跑時關閉窗格 |
| `session.start` | 註冊 `/agents`；讀一次環境變數 `CLAUDE_CODE_FORCE_TERMINAL_IMAGES`（決定小人畫圖片版還是方塊版）；用 `$.agent.list()` 補上這一批裡還在跑、但沒有紀錄的子代理（類型取 `type`；造型編號依清單順序取還沒用掉的最小號碼）；需要的話接回計時器與狀態列 |
| `session.end` | 停掉計時器；`/clear` 時清空批次與狀態列 |

所有 hook 只觀察：記錄失敗就略過，一律照原樣交回 `next(e)` 的結果，不擋任何事件。

## 數字的算法

| 欄位 | 算法 |
| --- | --- |
| token | 有 `reportedTokens`（前景子代理完成後 Claude Code 自己算的總計）時用它；否則用 `lastUsage` 的四種 token 加總（輸入、cache 讀、cache 寫、輸出） |
| ctx % | `lastUsage` 的輸入、cache 讀、cache 寫加總，除以該模型的 context 上限；上限未知時不顯示 |
| 時間（卡片） | `startedAt` 到 `endedAt`；還在跑就算到現在。格式 `m:ss`，滿一小時 `h:mm:ss` |
| 這一步耗時 | `activityStartedAt` 到現在，只在執行中顯示 |
| 卡住 | 正在做什麼是「思考中」且這一步超過 5 分鐘，或是工具且超過 3 分鐘 |
| 整批耗時（狀態列） | 最早的 `startedAt` 到最晚的 `endedAt`，還有在跑就算到現在 |
| 狀態數量（狀態列） | 執行中、完成、失敗各幾個；數量 0 的不列 |
| token 的顯示 | 未滿 1000 照寫；未滿 100 萬四捨五入到 k（`26k`、`150k`）；滿 100 萬取一位小數（`1.2M`） |

context 上限集中在 `pricing.ts`，註明資料日期與來源（claude-api skill）；不憑記憶寫。

## 開關時機與 /agents

| 情況 | 動作 |
| --- | --- |
| 這一批出現第一個子代理 | `$.ui.open({ id: 'agent-panel', title: 'Agents', columns: 42 })`，不帶 `focus` |
| 同一批再派子代理 | 只更新資料 |
| 使用者本人送出一般訊息（`origin.kind` 是 `composer` 或 `bridge`，文字不是 `/` 開頭） | 這一批還有子代理在跑：不關；全部結束：`$.ui.close({ id: 'agent-panel' })` |
| `/` 開頭的指令、背景任務的通知、外掛或其他 session 送的訊息 | 不關 |
| `/agents` | 窗格已放上畫面就關閉；否則開啟並顯示最近一批 |
| 使用者按 ✕ 或 ctrl+x x | 照常關閉；這會清掉「親手開過」的紀錄，之後要再打一次 `/agents` 才能在 110 欄自動跳出 |
| `$.ui.open` 回傳 `isPlaced: false` | 窗格在背景等待，終端機變寬時自動出現；每個 session 最多跳一次提示「子代理面板放不下：打 /agents 開啟」 |
| 有子代理在跑、但面板沒放上畫面 | `$.ui.status('Agents  ●2 ✓1 ✗1')` 在輸入框下方釘一行；全部結束或面板放上畫面後 `$.ui.status(undefined)` 清掉 |

狀態列只在派出、完成與面板開關時更新，不跟動畫計時器走，所以不放會一直跳動的耗時。

動畫與計時：只在「窗格已放上畫面而且有子代理在跑」時，用 `$.clock.every(200)` 遞增 `tick`；沒有子代理在跑或窗格關閉就停止。彗星、時間、這一步耗時與卡住判斷都在畫面時依當下時間計算，跟著 `tick` 更新；小人走路也用同一個 `tick`，每 3 拍（0.6 秒）換一次腳，不另開計時器。`tick` 只有面板讀，不用 `$.ui.invalidate`，避免整個對話紀錄重畫。

## 錯誤處理

| 情況 | 處理 |
| --- | --- |
| hook 內部出錯 | 略過這次記錄，照原樣回傳 `next(e)` 的結果 |
| 畫面丟例外 | 接住，畫一行紅字「面板暫時畫不出來：原因」，不讓 Claude Code 卸載窗格 |
| context 上限表裡沒有的模型 | 認得系列與版本時顯示名稱，否則顯示原始 id；不顯示 ctx % |
| `usage` 為 null | 不覆寫 `lastUsage`，不當成 0 |
| 熱重載或面板開啟前就在跑的子代理 | `session.start` 與開新一批時用 `$.agent.list()` 補上，用量從之後的請求開始累計 |
| 派出被擋下（`deny`） | 不加入 |
| workflow 遠端子代理（沒有 `agentId`）、teammate（有 `teammateId`） | 不列入 |
| 窗格放不下 | 見上表：只提示一次，有子代理在跑時輸入框下方顯示狀態列 |
| 沒有設定 `CLAUDE_CODE_FORCE_TERMINAL_IMAGES` | 退回方塊版（`Raster`） |
| 設定了 `CLAUDE_CODE_FORCE_TERMINAL_IMAGES`，但終端機不支援 kitty 圖片 | mod 分不出來，會出現亂碼或空白；靠開啟方式避免：只在 cmux、而且不在 tmux 時設定（見文末「2026-10-10 圖片版小人」） |
| 非終端機畫面（例如桌面版）、扣掉小人後文字區不到 24 欄 | 不畫小人，卡片文字用整個寬度 |
| 舊版程式記錄、沒有 `look` 的列 | 小人畫第一種造型（天線） |
| session 結束、`/clear` | 停計時器；`/clear` 清空批次與狀態列 |

## 完成標準

1. 終端機 113 欄、打過一次 `/agents` 之後，派出子代理時面板自動跳出；面板沒放上畫面時，輸入框下方有一行狀態列
2. 每個子代理的類型或 name、描述、模型、effort、工具次數、正在做什麼與這一步耗時、ctx、token、時間隨執行更新；完成後顯示 ✓ 與最終 token，失敗時顯示原因與停在哪個動作；畫面上沒有費用
3. 工具超過 3 分鐘、思考超過 5 分鐘時，那一列轉黃
4. 子代理還在跑時送出訊息，面板不關；全部結束後的下一則訊息才關；打 `/` 指令時不關
5. 完整模式每張卡片左邊有像素小人：配件依派出順序換，跨回合還在跑的保留原本的造型；執行中走路，卡住停下變黃，完成閉眼，失敗變灰；精簡模式、文字區太窄、非終端機畫面時不畫；卡片列數不變，相鄰的完成卡片之間空一列，小人不會上下黏在一起
6. 在 cmux 設定 `CLAUDE_CODE_FORCE_TERMINAL_IMAGES` 並重啟背景服務後，小人是 4 欄 × 2 列的細像素圖片版，各狀態跟第 5 點一樣；沒有設定時是方塊版
7. 驗證完成後停用 `agent-radar@claude-code-mods`（停用 user 範圍外掛若被 auto mode 擋下，請使用者用 `!` 執行）

## 2026-10-09 改版

起因：使用者以主管模式工作，常平行派出多個子代理，要一眼看出誰在做什麼、有沒有卡住或失敗。原本的面板偏重用量與費用，而且一個子代理佔 5 列，派出三、四個就要捲動。

1. 不顯示費用：畫面拿掉 Cost 與 ≈$，刪掉單價表與費用資料（`costUsd`、`hasUnpricedUsage`），`pricing.ts` 只留算 ctx % 需要的各模型 context 上限。原因：API 不給美元費用，token 乘單價只能估算（連 cache 存多久都分不出來），數字不可靠又要維護單價表；面板改成專注在進度
2. 關閉時機：使用者本人送出一般訊息時，這一批還有子代理在跑就不關，全部結束後的下一則才關；`/` 開頭、背景通知、外掛送的照舊不關。原因：主管模式下常邊等子代理邊補指令，面板要留著看進度
3. 狀態列取代統計方框：頂端一列「Agents  ●2 ✓1 ✗1」加靠右的整批耗時，數量 0 的不列；token 只顯示在卡片上。原因：方框佔 4 列只放兩個數字；一列就能看出幾個在跑、幾個完成、幾個失敗
4. 卡片標題改成「類型（或 Agent 的 name） · 描述」，耗時靠右放在標題列。原因：Claude Code 自己的子代理清單（↓ to manage）第一段就是類型或 name，可以對照；清單第二段是 Claude Code 另外產生的進度摘要，mod API 拿不到
5. 卡片收緊：分組改成 Running → Failed → Done；執行中 4 列＋彗星進度條，完成 2 列，失敗 3 列（紅字寫失敗原因與停在哪個動作），完成與失敗不畫進度條；拿掉卡片間的分隔線，組與組之間空一行。原因：平行派出多個時要一個畫面看完；失敗的排在完成前面比較容易注意到；已結束的不需要進度條
6. 即時動作與卡住提醒：子代理每次送出請求時正在做什麼改成「思考中」，呼叫工具時改成工具描述，並記下這一步開始的時間；工具超過 3 分鐘或思考超過 5 分鐘，那一列轉黃、進度條變成靜止的黃色。原因：原本只在呼叫工具時更新，子代理在思考時看起來像停在上一個工具；有了開始時間才分得出是在忙還是卡住
7. 精簡模式：面板放在輸入框上方（`placement` 是 `inline`），或完整模式需要的列數超過面板可見列數（`scroll.bodyRows`）時，每個子代理只畫一列（狀態、標籤 · 描述、正在做什麼或失敗原因、耗時）。原因：放在輸入框上方時會擠掉對話的空間；子代理多時完整模式要捲動才看得完
8. 狀態列保底：有子代理在跑、但面板沒放上畫面時，用 `$.ui.status` 在輸入框下方釘一行「Agents ●2 ✓1 ✗1」，全部結束或面板放上後清掉；只在派出、完成與面板開關時更新。原因：終端機不夠寬時面板在背景等，原本只跳一次提示，之後就看不到子代理的狀態；不跟動畫計時器走，避免一直重畫輸入框下方

## 2026-10-10 像素小人

起因：使用者想讓每個子代理在面板上有一個看得出是誰的小圖示，參考了其他工具用像素小人區分子代理的做法。第一版造型由使用者看過彩色預覽後確認，之後可能再調整。

1. 卡片左邊加像素小人：完整模式每張卡片左邊 7 欄畫小人（後來縮小成 5 欄，見「2026-10-10 縮小方塊版小人」），跟文字之間空 1 欄，卡片文字區少 8 欄；執行中畫大小人（4 列、8 個像素高：配件 3、身體 4、腳 1；後來縮小成 3 列、6 個像素高，見「2026-10-10 縮小方塊版小人」），完成與失敗畫小小人（2 列、4 個像素高：配件 2、眼睛和手 2，沒有腳）。卡片列數（執行中 5、完成 2、失敗 3）不變；完整模式需要的列數原本也不變，後來完成卡片之間多了空行（見第 6 點）。原因：只靠類型與描述要讀字才分得出誰是誰，配件的形狀與顏色一眼就能對上；小人塞進卡片原有的列數裡，完整模式不會因此更早放不下
2. 用 `Raster` 畫，不用真圖片：新增 `hooks/mascot.ts`，把像素圖轉成 `Raster` 的格子，半格方塊 `▀`／`▄`／`█` 讓一格畫上下兩個像素，眼睛那一格改用一般字元、背景是身體色。原因：`Image` 元件要終端機支援 kitty 圖片協定，cmux 能不能顯示無法確認；`Raster` 只用字元與顏色。「不做的事」原本的「不畫像素頭像」改成不用真圖片。同日後來確認 cmux 能顯示 kitty 圖片，加上圖片版、這一版改稱方塊版，「不做的事」也跟著改（見「2026-10-10 圖片版小人」）
3. 7 種造型依派出順序輪流：天線、牛仔帽、耳機、鴨舌帽、安全帽、巫師帽、毛帽（顏色見「小人的造型與顏色」）。派出時把造型編號記進 `AgentRow.look`，挑這一批裡還沒用掉的最小號碼（熱重載補上的列也一樣）；舊版程式記錄、沒有編號的列畫第一種。小小人保留配件的形狀與顏色線索。原因：跨回合還在跑的子代理保留原本的造型，新派的不會跟它撞，超過 7 個才會重複；從執行中到結束都認得出是同一個子代理
4. 小人跟著狀態變：身體 `#d97757`、眼睛 `#1f1f24`；執行中眼睛 `•`、兩腳交替走路，每 3 拍（0.6 秒）換一次腳，跟彗星進度條共用同一個計時器；卡住時停下、身體變黃 `#e5c07b`；完成時閉眼 `^`；失敗時眼睛 `×`、身體轉灰 `#8a8a94`；配件在任何狀態都保留原色。原因：不讀字也看得出狀態；卡住的黃跟卡住的進度條同色；配件不變色，結束後還認得出是哪一個
5. 不畫小人的情況：精簡模式（一個子代理一列）；面板扣掉 8 欄後文字區不到 24 欄（後來縮小成 5 欄、扣 6 欄，見「2026-10-10 縮小方塊版小人」）；拿不到 `Raster` 元件（非終端機畫面）。原因：精簡模式一列放不下小人（小小人也要 2 列）；太窄時文字比小人重要。加上圖片版後，第三種改成看是不是終端機畫面（見「2026-10-10 圖片版小人」）
6. 完成卡片之間空一列（同日補修）：畫小人時，卡片不比它的小人高、而且同組後面還有卡片，就在兩張之間空一列；組的第一張之前、最後一張之後不加，不畫小人時也不加。`fullRowCount` 改成 `fullRowCount(batch, { withMascot })`（加上圖片版後再改成 `{ mascot: 'image' | 'raster' | null }`，見「2026-10-10 圖片版小人」），跟畫面共用 `groupEntries` 決定空列放哪；`register.tsx` 用實際會不會畫小人（夠寬而且拿得到 `Raster`）算列數，再決定要不要切精簡模式。原因：執行中卡片 5 列配 4 列的大小人（後來縮小成 5 欄、3 列，見「2026-10-10 縮小方塊版小人」）、失敗卡片 3 列配 2 列的小小人，小人底下都有空隙；完成卡片只有 2 列，剛好被小小人佔滿，Done 組相鄰兩張的小人上下貼在一起，上一隻的眼睛直接接到下一隻的帽子，看起來像一隻很高的怪小人。規則看卡片與小人的列數、不寫死完成卡片，之後卡片或小人的尺寸改了也成立；空列跟組間空行一樣畫成一個空白字元的 `Text`，不用 margin，列數才算得準

已知取捨：

- 7 個像素寬放不下四隻分開的腳：四隻腳兩兩相鄰，走路時內外兩對輪流著地（後來縮小成 5 欄、改成兩隻腳，見「2026-10-10 縮小方塊版小人」）
- 黃色安全帽在卡住時跟變黃的身體顏色接近，靠形狀與亮度分辨
- `•`、`×` 跟方塊字元同屬寬度不明確的 Unicode 字元，風險與面板現有的進度條 `▆` 相同

## 2026-10-10 圖片版小人

起因：使用者覺得方塊版小人太大：方塊字元一格只能畫上下兩個像素，像素很粗，想要像參考圖那樣小而細。

1. 圖片版小人：有設定環境變數 `CLAUDE_CODE_FORCE_TERMINAL_IMAGES`（非空）、而且是終端機畫面、拿得到 `Image` 元件時，用 `Image`（kitty 圖片協定）畫 16×16 像素的小人，最近鄰放大 4 倍成 64×64 後交給終端機縮放到 4 欄 × 2 列；執行中、完成、失敗都一樣大。卡片文字區少 5 欄（小人 4＋間隔 1），方塊版是 8 欄（後來方塊版縮小成 5 欄、少 6 欄，見「2026-10-10 縮小方塊版小人」）。原因：圖片的一個像素比半格方塊小很多，同一套造型可以畫得小而細；先放大成整數倍再交給終端機縮放，邊緣比直接放大 16×16 清楚；4 欄 × 2 列大約是正方形，畫布也用正方形，縮放才不會變形
2. 用環境變數判斷，沒有就維持方塊版：沒有那個變數時維持方塊版（`Raster`）；桌面版或精簡模式不畫。`register.tsx` 在 `session.start` 讀一次環境變數。原因：mod 沒辦法得知終端機最後到底有沒有開啟圖片（畫不出來時 `Image` 只畫 `alt` 文字）；Claude Code 2.1.295 的圖片開關裡，這個變數優先順序最高，非空就開，會蓋過「背景 session」與「tmux」的關閉判斷，所以有設定就代表圖片會開。cmux 實測能顯示 kitty 圖片，但 Claude Code 從 `TERM` 認不出 cmux，背景 session 預設也不開圖片，所以要強制開
3. 造型沿用方塊版：使用者確認過的 7 種配件與顏色，依派出順序輪流。16×16 畫布：配件 5 列、身體 12×8、兩側小手伸到畫布邊緣、四隻 1 像素寬 3 像素高的腳。表情：執行中 2×2 的點眼、完成 3×2 的 `^`、失敗 3×3 的 `×`；卡住身體黃 `#e5c07b` 停下，失敗身體灰 `#8a8a94`。走路：外側、內側兩對腳輪流抬起 1 個像素，每 3 拍換一次。原因：造型是使用者確認過的，換畫法不換角色，兩種版本認得出是同一批小人；畫布變大，四隻腳可以分開畫
4. 程式分工：新增 `hooks/mascot-image.ts`（`mascotImage({ look, state, frame })` 回傳 `{ rgba, width, height }`，同一組參數有快取、回傳同一個凍結物件；`MASCOT_IMAGE_COLUMNS = 4`、`MASCOT_IMAGE_ROWS = 2`）；`mascot.ts` 只多 export 共用的配色與編碼函式；`layout.ts` 以小人種類（image／raster）決定欄寬、列數與要畫什麼；`register.tsx` 在 `session.start` 讀一次環境變數。原因：面板每 0.2 秒重畫，快取讓同一張圖只算一次；配色只有一份，兩種版本的顏色不會分岔。同日後來 `mascotImage` 改成回傳 `{ png }`，像素不變（見「2026-10-10 圖片改傳 PNG」）
5. 相鄰完成卡片之間空一列的規則照舊：圖片版小人也是 2 列，完成卡片 2 列一樣被佔滿。規則本來就看卡片與小人的列數，不用改

怎麼開啟：在 shell 設定檔（例如 `~/.zshrc`）加入只在 cmux、而且不在 tmux 時開啟的設定。

```zsh
if [[ -n "$CMUX_SURFACE_ID" && -z "$TMUX" ]]; then
  export CLAUDE_CODE_FORCE_TERMINAL_IMAGES=1
fi
```

- 只在 cmux 開：不支援 kitty 圖片的終端機強制開啟，會出現亂碼或空白
- 不在 tmux 開：tmux 不會把圖片轉給終端機
- 背景 session 會繼承背景服務（`claude daemon`）啟動時的環境變數，所以改完設定後要開新分頁，執行 `claude daemon stop --any`（會結束所有背景 session，對話保留），再從新分頁 `claude attach` 或 `claude --resume` 接回

已知取捨：

- 原生 Ghostty 或 kitty 裡沒設這個變數時會看到方塊版：mod 只看環境變數，不自己判斷終端機
- 走路只抬 1 個像素，比方塊版不明顯
- 熱重載後，面板如果在 `session.start` 讀到環境變數之前就先重畫，會先畫方塊版，下一次重畫才換成圖片版：有子代理在跑時 0.2 秒內就會換，全部結束時要等下一次狀態改變
- 不用 `settings.json` 的 `env` 設定：它會套用到所有終端機，而且無法確認它在 Claude Code 判斷圖片能力之前就生效

## 2026-10-10 失敗卡片細節

起因：使用者在實際畫面上看到失敗卡片的第 3 列只有「Opus 5.5 · 1 tools」，資訊比完成卡片少（沒有 effort 與 token），而且 `1 tools` 文法不對。

1. 失敗卡片第 3 列跟完成卡片一樣：寫「模型 · effort · N tools · token」，effort 沒有值時不寫；失敗原因那一列與卡片列數（3 列）不變。`layout.ts` 把完成與失敗卡片共用的細節（effort、工具次數、token）抽成 `finishedDetails`，兩種卡片的模型列由同一個函式產生。原因：失敗的子代理一樣用掉了 token，也要看得出用哪個 effort、失敗前做了多少事；共用同一組細節，之後改格式不會只改到一邊
2. 工具次數分單複數：1 次寫 `1 tool`，0 次與 2 次以上寫 `N tools`。執行中、完成、失敗卡片共用 `toolsText`，一起套用；精簡模式不顯示工具次數，不受影響。原因：`1 tools` 文法不對

## 2026-10-10 圖片改傳 PNG

起因：使用者在 cmux 實際畫面上看到，面板與輸入框附近印出大量 `/Zd1f/2XdX/9l3V/…`、`AAAA…`，面板文字也被打亂。比對後確認是小人圖片的像素資料：`2XdX/9l3V//Zd1f/` 是身體色 `#d97757` 不透明像素的 base64，`AAAA` 是透明像素。原本每張圖是 64×64 的 RGBA，base64 有 21,848 個字元，kitty 序列得切成好幾段；背景 session 的畫面要經過背景服務的 pty 轉送，序列中途被切斷，後半段的像素就被當成文字印出來。

1. `Image` 的來源從 `{ rgba, width, height }` 改成 `{ png }`：像素不變（16×16 造型、最近鄰放大成 64×64），壓成 PNG 後每張只有幾百個 base64 字元，一個 kitty 序列就送完。原因：先前用 PNG 在 cmux 一般分頁測試時顯示正常；序列不必切段，就沒有中途被切斷的問題
2. 新增 `hooks/png.ts`：自己實作 zlib／deflate（RFC 1950／1951），只用一個固定 Huffman 碼的區塊，加上只找「左邊那個像素」與「上一列同位置」兩種回頭距離的 LZ77；每列的 filter byte 一律是 0。原因：hooks 的執行環境沒有 Node、沒有 `CompressionStream`，`claude plugin validate` 也不讓 import `node:zlib`；小人是放大過的大色塊，找這兩種距離就壓得很小
3. 測試：新增 `tests/png.test.ts` 與測試用的解碼器 `tests/png-decoder.ts`，檢查 PNG 結構（簽章、IHDR、CRC、IEND）並把 PNG 解回 RGBA；`mascot-image` 原本關於像素的測試全部改在解回的像素上檢查，另外檢查每張 base64 小於 4096 字元。真實 session：使用者在 cmux 確認小人正常、沒有 base64 亂碼，完成後閉眼

## 2026-10-10 縮小方塊版小人

起因：使用者覺得方塊版小人太大。圖片版雖然小而細，但要背景服務（`claude daemon`）的環境裡有 `CLAUDE_CODE_FORCE_TERMINAL_IMAGES` 才會出現；背景服務從舊的 Claude 程序繼承環境時常常沒有這個變數，所以方塊版是常見的畫面。

1. 縮小尺寸：方塊版小人從 7 欄改成 5 欄（`MASCOT_COLUMNS = 5`），跟文字之間照舊空 1 欄，卡片文字區從少 8 欄變成少 6 欄，42 欄的面板文字區從 34 欄變成 36 欄。文字區至少 24 欄才畫的門檻不變，所以方塊版要面板 30 欄以上才畫（原本 32 欄）。執行中的大小人從 4 列、8 個像素高改成 3 列、6 個像素高（配件 2、身體 3、腳 1）；完成與失敗的小小人一樣是 2 列、4 個像素高（配件 2、眼睛和手 2，沒有腳），寬度跟著變成 5 欄。原因：使用者覺得太大；小人變窄，文字區多 2 欄，描述與動作比較不會被截斷
2. 身體與腳：身體 3 個像素寬，眼睛與兩側小手那一格（`▄•█•▄`）跟小小人相同，大小人只多最下面一列（身體底部與腳）。腳從四隻改成兩隻，停著時都著地，走路時左右輪流抬起一隻，每 3 拍（0.6 秒）換一次，只有腳那一列會變。原因：5 個像素寬扣掉兩側的手，身體只剩 3 個像素，只放得下兩隻分開的腳；執行中換成完成時只少了腳那一列，一眼看得出是同一隻
3. 配件簡化：7 種配件的顏色、palette 與輪流順序不變，形狀從大小人 7 個像素寬、3～4 個像素高（小小人另有一份 2 個像素高的）簡化成一張 5×2 像素圖，剛好畫在最上面一列格子，大小人與小小人共用。天線的底座、毛帽的深綠色反摺畫不下，只有圖片版保留。原因：配件只佔一列，下面的身體每種造型都一樣，只靠主色與輪廓分辨；兩種大小共用同一張，從執行中到完成配件完全不變
4. 不變的部分：各狀態（執行中走路、卡住停下變黃、完成 `^`、失敗 `×` 轉灰）、卡片列數（執行中 5、完成 2、失敗 3）、相鄰完成卡片之間空一列的規則（完成卡片 2 列、小小人 2 列，照樣會黏在一起）、圖片版（4 欄 × 2 列）都沒動
5. 測試：`mascot.test.ts` 的尺寸改成大小人 5×3、小小人 5×2，各大小、各狀態都檢查 `Raster` 的欄列數跟格子一致；配件可分辨的測試改成大小人、小小人都測，另外新增「配件只畫在最上面一列」與「身形」（逐字比對眼睛那一列、兩隻腳停著與走路的樣子）；換腳的測試加上最下面一列一定會變；狀態的測試改成直接比對眼睛字元。`layout.test.ts`、`render.test.tsx` 的欄寬與門檻跟著改（42 欄文字區 36 欄、面板 30 欄畫、29 欄不畫），`layout.test.ts` 另外檢查 30～80 欄的文字區都是面板寬減 6。整套 146 個測試通過

已知取捨：

- 配件只剩 5×2 像素，細節比較少：天線的底座、毛帽的反摺畫不下，主要靠顏色與大致輪廓分辨
- 只剩兩隻腳：走路時一次只有一隻著地；圖片版仍是四隻腳，兩種版本的腳數不同
